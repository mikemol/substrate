## Step 1 — Halt and name the target

Migrate the three bare data types in
[Substrate/Cocycles/V4Signature.agda](Substrate/Cocycles/V4Signature.agda)
(`Pairing`, `Chirality`, `OrbitKey`) to F₂-linear structural
representations, with universal-property bridges back to the existing
data types so existing consumers continue to type-check.

Current bare definitions (lines 54-91):

```agda
data Pairing : Set where α-pair β-pair γ-pair : Pairing
data Chirality : Set where even odd : Chirality
OrbitKey : Set
OrbitKey = Pairing × Chirality
```

These are predicate-style enumerations. The migration turns each into
a derived form of the M-1..M-9 F₂-linear machinery (commits 93f85df
through de23207).

## Step 2 — Search for repeatable form

All three types decompose under the same pattern:

| Bare type | Structural meaning (per catalog § CY-5) | F₂-linear realisation |
|-----------|----------------------------------------|----------------------|
| Pairing | V₄'s 3 non-identity elements; "which axis-pair is in the orbit" | 3 nonzero vectors of F₂² (a strict subset of `Vector 2`) |
| Chirality | Z/2; parity of underlying S₃ permutation | F₂ itself (M-1) |
| OrbitKey | Pairing × Chirality = 6-orbit index | (F₂²-nonzero) × F₂ |

Repeatable form: **finite-set ↔ F₂-linear-derived bijection**. Each
case is a small bridge with its own basis-case enumeration but
composes via the universal-property machinery already built.

## Step 4 — Name the composition

The composition graph:

```
M-1 (F₂) ─────────────────┐
                          │
M-2 (Vector 2 = F₂²) ─────┼─── N-2 (V4-Nonzero as Fin 3 + coords)
                          │       │
                          │       ├─── N-3 (Pairing bridge)
                          │       │
M-1 (F₂) ─────────────────┘       ├─── (×)
                                  │       │
M-4 (F₂) ─────── N-4 (Chirality   │       ↓
                       bridge) ───┴─── N-5 (OrbitKey bridge)
```

Each bridge composes via the universal property of bijections:
forward, backward, both round-trips. Bridges compose pairwise via
product. Universal-property records carry the bridge data.

## Step 5 — Name the entailment

**Entailment claim:** For each existing function `f : OrbitKey → X`
in `V4Signature.agda` and its downstream consumers, there is a
function `f' : (V4-Nonzero × F₂) → X` such that `f ≡ f' ∘ to-product`
(where `to-product = N-5.to`). Replacing call sites of `f` with
`f' ∘ to-product` preserves typing; replacing `OrbitKey` with
`V4-Nonzero × F₂` is the migration.

**BHK content**: the bridge IS the proof transformer. Given a proof
about OrbitKey, the bridge converts it to a proof about
V4-Nonzero × F₂. Given a proof about the structural form, the bridge
converts back.

## Step 6 — Multi-angle reserve

If N-2's Angle B (Fin 3 + coords) hits unforeseen complications, fall
back to:

- **Angle A**: Σ V₄ (λ v → v ≢ 𝟎). Pattern-matching is uglier but the
  type IS a subset of V₄ structurally. Useful if downstream consumers
  need the V₄ arithmetic on V4-Nonzero directly.
- **Angle C**: Vec F₂ 2 with a decidable `is-nonzero?` predicate, and
  `V4-Nonzero = Σ (Vector 2) (T ∘ is-nonzero?)`. More general but
  more boilerplate.

Pick Angle A if the consumer-side cleanly uses V₄ arithmetic on the
nonzero element; otherwise stay with B.
