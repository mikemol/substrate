CLAUDE.md fires the reuse-search trigger on "build a NEW def/lemma/module." But the same under-survey recurs on **feasibility/difficulty conclusions** — and those skip the trigger. Caught 2026-06-25 (Ⓕ.tower-crossmul): I called F₂/ℚ coprimality "doubly awkward" for a direct CrossMix. User: *"we have the chinese remainder theorem and stepwise euclid's extended algorithm and bezout all formalized in this repository precisely for this kind of thing."* The coprime/orthogonal case is the CRT-CLEAN case, gcd is the residue gauge, EEA/Bézout the engine — all formalized ([[reference_residue_is_bezout_gcd_eea_spine]]). My "awkward" was an under-surveyed feasibility judgment.

This is the family: declaring a thing **awkward / gated / the wrong shape / suboptimal / hard** is a NEGATIVE conclusion that should trip the reuse-search just as hard as "build X" does. Sibling of [[feedback_wall_can_wear_a_negative_theorem]] (the *impossibility* extreme) and [[feedback_declaring_a_wall_is_the_rebuild_reflex]] — this is the weaker, far more frequent case: not "impossible," just "ugh, this is awkward," asserted before checking.

**THIS MEMORY DID NOT FIRE (2026-06-25, re-caught same day).** Banked at one reground, violated at the next: I scoped Ⓕ.tower-CRT as "new reach off the primes" and Ⓕ.cyclotomic as "gated," WITHOUT searching the witness tower — where `PhiMultiplicity` (mult2/nullity2, mult2-fibered fully PROVEN) and `CycleType` (the full conjugacy/partition census = the combinatorial char-poly/cyclotomic decomposition) already carry it. The memory layer is recall-gated, so it silently no-ops at the moment of the claim. Hence the escalation to CLAUDE.md (Ⓜ.claude-md-widen). Two SHARPENINGS:
  1. **A deferral/TODO comment is a HYPOTHESIS, not a fact.** "deferred to Ⓧ" / "not yet built" in a header is something to VERIFY by searching for the actual provider — it may be stale, or point at a *different* deferral sharing a tag (Ⓕ.face's face-action core WAS done in LcmCoprime; only the separate Ⓕ.cyclotomic divisor-product is open). Don't propagate a comment's claim as ground truth.
  2. **Search the WITNESS TOWER specifically** for any spectral / multiplicity / cycle / conjugacy / decomposition / combinatorial-count claim. `WitnessTower/{PhiMultiplicity,CycleType,FaceCount,SupportGrading,Decompose}` is a SILO I don't auto-search when scoping the Algebra/Linear spectral side — and it usually already has the combinatorial half.
  3. **A residue-SHAPE claim is an absence-claim too (2026-07-10, Ⓖ.orientation-rig).** When deferring the leftover of a build, "X is *up-to-iso only* / *coherence-only* / *the categorified next arc*" is a claim about X's shape asserted without probing it — same family as "awkward/deferred." Caught: I banked the graded Lehmer rig's ordering-level laws as uniformly "up-to-iso coherence" in a commit message; the one-line probe (state the law as a grade-transport `subst`, check the base case) showed ⊕-**assoc is STRICT** (base = refl, no permutation) — only comm/distrib are genuinely iso. The residue split by the wedge's own r (r=id strict vs r=transposition iso), invisible until probed. **Apply:** before writing that a deferred remainder is "up-to-iso/coherence/categorified-only," write the ONE-LINE type-level probe (the transport statement + base case) — it costs a scratch file and either confirms the shape or splits the residue.
  4. **A "FLOOR / doesn't-lift / can't-genericize" conclusion about your OWN just-built structure is an absence-claim — and I wrote it into the LEDGER as a finding before it dissolved (2026-07-10, Ⓖ.orientation-lift-generic).** After lifting three generic invariants (GradedHomOver/Braid/BraidNatural), I declared the 4th level (⊕map/⊗map, the bifunctor-on-morphisms) "decomposition-BOUND, does not lift — the recursion's floor, coinciding with the Set₁ boundary" and RECORDED it as a structural finding. Wrong: the user said "Tackle ⟡rig-UP-map" and it lifted cleanly in one build (GradedBifunctor, first-try green). The error: I checked "are the functoriality laws PROVEN?" (no) and concluded "so it can't lift" — conflating **not-yet-built with can't-be-built**, AND reasoning about the wrong content (the char lemmas ⊕map-inject/⊗map-combine ARE decomposition-bound, but the *functoriality laws* gmap-id/gmap-∘ that MAKE a bifunctor are decomposition-FREE, exactly like braid-invol). **The tells, both load-bearing:** (a) a floor/impossibility conclusion about my own work is the strongest absence-claim of all, yet the one I probe LEAST because it feels like earned insight from having just done the work; (b) **the user saying "tackle X" right after I called X a floor is the signal to RE-PROBE X, not to defend the floor** — they can see the dissolve I can't. **Apply:** before writing "floor / bottoms-out / doesn't-lift / can't-genericize" (especially into a durable ledger), state what the lifted invariant's LAWS would be and ask "are THOSE laws decomposition-free / already-provable?" — not "is it already built?"

**Why:** the substrate is dense and deliberately built so the hard/awkward thing is already handled (CRT/EEA/Bézout for coprime split+reconstruct; CrossMix grading for residues; the setoid ladder for ℚ). An under-surveyed "awkward" both wastes the existing machinery and mis-reports the landscape to the user.

**How to apply:** before writing "X is awkward/gated/infeasible/the-wrong-shape" — STOP and run the structural reuse-search (`jea_pysim.py --clusters`, scan Registry/Generators/apex memories, grep the obvious module names). Name the existing machinery that handles X, or confirm briefly there isn't one. The trigger is the negative judgment itself, not just the build. See CLAUDE.md "Reuse-search BEFORE building" + [[similarity-not-grep]] — this widens its scope from builds to conclusions.
