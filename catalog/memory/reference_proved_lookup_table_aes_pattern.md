For FAST verified computation over a finite domain in `--safe` Agda (permutations, S-boxes, modular/cyclic ops, orbit frames), use the **proved-lookup-table pattern**, exemplar `Substrate.Algebra.F2.Polynomial.Wedge.SBoxTable`:

1. A cheap **lookup** `idx : Vec A n → ℕ → A` into a precomputed table (e.g. `SBOX : Vec ℕ 256`).
2. **Bank correctness ONCE** by exhaustive reflection: `all-vec (λ a → idx TABLE (val a) ==? construct a) ≡ true` by `refl` (forces the expensive construction over the WHOLE finite domain a single time; `all-vec`/`all-vec-sound` live in `…Wedge.GUnit`). `all-vec-sound` then extracts any per-element fact.
3. Expose the cheap form `f = decode ∘ idx TABLE ∘ encode` and prove `f ≡ construction` (`sbox≡gf`). Consumers force a **table index, not the construction** (AES KAT forces a byte lookup, not a GF(2⁸) inversion) — rigor banked, evaluation O(1).

**When it pays / when it doesn't (the economics — learned the hard way):** the win is `(once · bounded) ≪ (many · per-use)`. It needs (a) per-element cost BOUNDED and (b) repeated forcing. AES qualifies: GF inversion runs on `Vec F₂ 8` BIT-VECTORS (~0.2s/byte × thousands of round-forcings). It does NOT rescue unary-ℕ `_mod-suc_`: that is ~O(a·b) `suc`/`<` reductions (60 mod 15 ≈ 60s+ for ONE product; ℤ/8 stays small, ℤ/15 times out at 120s), and a table would re-force those same reductions to verify itself. **Fix slow finite-domain compute by a BOUNDED bit-vector / Fin-n carrier (like AES bytes), not unary ℕ + mod-suc.** For one-off small facts, just use small representatives (ℤ/6 not ℤ/15).

Drove **Ⓟ** (orbit-cloud frames as `PermTable = Vec (Fin n) n` proved-bijection lookup tables, `ElAtlas.OrbitCloud`) and the cost analysis of [[feedback_finite_window_constructive_lem]] / the Ξ★ numeral rungs. User pointer: "how the AES code accelerates these permutations by lookups against a proved table."

**The COMPOSITION wall (mat260 xtime ask, 2026-06-19 — the table does NOT make a deep pipeline `refl`-able):** I replicated the pattern for `xtime` (`GF256.XtimeTable`: `xtime-is-aes`, cheap `xtime-tab`) and routed MixColumns through it (`MixColumns.Fast`, `mix-fast≡mix` proven, `Round.MixColumns = map mix-fast`) — each PER-OP is cheap (idx over 256 in <0.5s; `XtimeTable`/`Fast` compile in ~3s). But the full-encrypt KAT `encrypt-key key-C1 pt-C1 ≡ ct-C1` by `refl` STILL blew up: **measured > 30 min wall, > 5.6 GB resident, not done.** Cause: the 10-round COMPOSITION (~450 byte-ops chained) — even with cheap tables, `byte-val`/`idx`/`nb` produce/walk **unary ℕ** and Agda's normaliser has **no term sharing**, so intermediate state terms compound. The cheap table fixes per-op cost; it does NOT fix deep-composition normalisation. **Lesson: a proved table makes a SINGLE finite-domain op cheap, NOT a long pipeline of them — `refl` over a deep composition is its own wall (unary-ℕ + no sharing), independent of per-op cost.** What IS feasible: the COMPONENT KAT (one MixColumns column `[d4 bf 5d 30]→[04 66 81 e5]`, `mixcolumns-kat = refl`, cheap). The e2e identity stays oracle-validated; commit a,b,c + the component KAT, report (d) as evaluator-bound (NOT a correctness gap — every component FIPS-pinned). Also: the full-build gate caps each module at **600 s / 1 GB** (`+RTS -M1024m`), so an evaluator-heavy `refl` is uncommittable by construction. Twin of the unary-`mod-suc` economics above.

**RESOLVED — the full-encrypt KAT IS feasible (Ⓚ✂, 2026-06-19, user's hint).** My "evaluator-bound / uncommittable" verdict above was WRONG (over-pessimistic). The fix is the **parameterized-module pattern** (cf. `Algebra.F2.MixColumns.Proof.G`) — what transits a module boundary is the KEY: a proof assembled INSIDE a module ABSTRACT over the keys/states has `round`/`fold`/`nextRoundKey` **stuck (neutral)** on the abstract args, so NO composition is ever normalised; it type-checks once, cheaply. Supply the concrete one-step pins (`KAT.KeyPins` per key step, `KAT.RoundN` per round, `KAT.Pre`/`fin`) and INSTANTIATE BY `open` — **not** a type-annotated re-declaration (which would re-run conversion and WHNF the composition). The substituted type then crosses the boundary with no conversion ⇒ the deep chains are never forced. Result: `encrypt-key key-C1 pt-C1 ≡ ct-C1` --safe, whole chain ~27 s (≤3 s/module). Note TWO deep chains had to be broken: the 10-round composition AND the key schedule (which is separately **exponential** to force — `nextRoundKey`'s word recursion has no sharing: 9 s/46 s/241 s for rk1/rk2/rk3). **Meta-lesson: "Agda can't normalise this deep composition" is rarely a real wall — stuff the painful part in a parameterized module so it's proven over abstract args (neutral, unforced) and instantiate by `open`. The concrete checkpoints (named intermediate literals) are the pins; the module threads them without re-forcing.** Sibling of [[feedback_test_the_wall_before_declaring_it]] — I declared the wall (twice: monolith, then per-round-cumulative which re-carried the residue via `XN`) before finding the module-boundary escape.
