## The authority question is OPEN, and that is deliberate

The `Stop`/`SessionStart` hook in `~/.claude/settings.json` runs `regen_if_stale.sh`
from the **`~/.claude` copy**, whose `MEM` and `S` paths are absolute. So today:

| | `~/.claude/.../memory/` | `catalog/memory/` (here) |
|---|---|---|
| read by the session | ✅ loaded as memory | ❌ |
| regenerated by the hook | ✅ live | ❌ |
| versioned / gateable | ❌ | ✅ |

⚑ **THE TWO WILL DIVERGE THE MOMENT EITHER IS EDITED, AND NOTHING DETECTS IT.** That
is the known cost of copying rather than moving; it was chosen so a working `Stop`
hook was not disturbed mid-flight. Resolving it means either pointing
`regen_if_stale.sh` at this directory (one authority, touches a live hook) or adding a
drift check. **Neither is done. Do not read this copy as current without diffing it.**

## What the pipeline is

`regen_if_stale.sh` is the driver, wired as a `Stop` + `SessionStart` hook. It is a
cheap mtime **gate**: it no-ops unless a memory `*.md` (or `synth_wire.py` itself) is
newer than `MEMORY.md`. When stale it launches, detached and single-instance under
`flock -n`, so it never blocks a turn:

    python3 synth_scale.py 4  &&  python3 synth_wire.py     # ~5 min

- `grammar_phrase_lattice.py` (17K, the largest) — the phrase grammar underneath everything
- `synth_apex.py` — builds the graded apexes into `synth/<slug>.md`
- `synth_scale.py` — the scaling pass; caches cluster phrases in `synth/.cluster_cache.json`
- `synth_wire.py` — emits the mesh ROOT (`MEMORY.md`) pointing at those apexes.
  ⚑ Writes a **candidate** `MEMORY.synth_wired.md`, not `MEMORY.md` in place.
- `synth_gate.py` — gates apex lines (every line witnessed by ≥2 members)
- `build_warrants.py` → `warrants.bib` (107K) — the claim-DAG over the corpus
- `cluster_memories.py`, `pcr_corpus_grammar.py` — clustering / corpus grammar
- probes: `synth_pi_probe.py`, `synth_reverse_probe.py`, `synth_typehole_probe.py`,
  `synth_grammar_read.py`, `chamber_coord_probe.py`
